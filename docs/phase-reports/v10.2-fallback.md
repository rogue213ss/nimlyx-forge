# V10.2 Gemini Fallback Matrix Implementation

## Files Changed
* `backend/services/llm/gemini_provider.py`
* `backend/tests/test_v10_2_gemini_fallback.py`

## Configuration Variables Added
* `GEMINI_API_KEY_2`: Optional secondary Google AI Studio / GCP API key. If present, it will be added to the rotation matrix.
* `LLM_FALLBACK_MODELS`: Comma-separated list of fallback models (e.g. `gemini-3.7-flash,gemini-2.5-flash`).

## Behavior Implemented

### Key Rotation and Model Fallback Matrix
The `GeminiProvider` now builds a combinatorial list of `(key, model)` pairs. 
For example, if `GEMINI_API_KEY` and `GEMINI_API_KEY_2` are both provided, and models `A` and `B` are configured, the matrix becomes:
`[(Key 1, Model A), (Key 1, Model B), (Key 2, Model A), (Key 2, Model B)]`

### Error Classification
* **Transient Errors:** Errors containing `503`, `429`, `500`, `502`, or `timeout` are caught and trigger an immediate matrix rotation with backoff.
* **Invalid Models:** `404` or `invalid model` errors trigger a fast matrix rotation (`0.5s` delay) without wasting long exponential backoff times, allowing the system to rapidly drop down to the next fallback model.
* **Permanent Errors:** Errors like `400 Bad Request` or `401 Unauthorized` instantly fail the generation block without entering the retry loop.

### Retry / Backoff Behavior
* Max attempts dynamically scales to `max(5, len(combinations))` to guarantee every configured permutation is attempted at least once.
* Retries utilize bounded exponential backoff (`base_delay * 2^attempt`) + random jitter (`0.0 - 1.0s`) to mitigate thundering herd effects on the API.

## Regression and Database Impact
* **Total Regressions:** `50/50` passing (45 existing + 5 new).
* **Database State:** Unchanged. The provider still safely raises a final exception after exhausting its retry matrix, allowing the `LLMScriptWriter` orchestration layer to cleanly catch the failure, mark the `ScriptRun` as `FAILED`, and roll back state without creating orphan `ScriptSentence` records.

## Limitations
* If Google's API enforces quota at the project-level and both `GEMINI_API_KEY` and `GEMINI_API_KEY_2` are tied to the exact same Google Cloud Project, a strict `429` quota exhaustion will still block both keys. Keys must belong to separate projects for true redundancy.
